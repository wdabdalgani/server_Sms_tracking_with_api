# بوابة SMS (مشروع `sm`)

وسيط ويب بلغة **PHP** يجمع بين واجهة إرسال يدوية، و**REST API** للأنظمة الأخرى، ثم يمرّر الطلبات إلى **بوابة إرسال SMS** إما عبر **السحابة** (مثل `api.sms-gate.app` مع تطبيق Android SMS Gate) أو عبر **Gateway محلي** على الشبكة الداخلية. تُسجَّل كل المحاولات في **MySQL** لأغراض التدقيق واستكشاف الأخطاء.

---

## 1. الهدف من المشروع

| الهدف | الشرح |
|--------|--------|
| **فصل المخاطر** | التطبيقات الأخرى لا تتصل مباشرة بمفاتيح مزوّد السحابة أو بعنوان الهاتف على LAN؛ تتصل بسيرفرك أنت (`api/send.php`) بمفتاح واحد تتحكم به. |
| **قناة موحّدة** | نفس منطق الإرسال (التحقق من الحقول، تنسيق JSON، Basic Auth، تسجيل النتيجة) يُستخدم من الواجهة البشرية ومن الـ API. |
| **مراقبة وتشخيص** | جدول `sms_logs` لمحاولات الإرسال الفعلية، وجدول `api_server_inbox` لطلبات السيرفرات الواردة عبر الـ API، مع صفحات عرض في الواجهة. |
| **مرونة النشر** | دعم وضع **سحابة** (الهاتف متصل بالإنترنت) ووضع **محلي** (HTTP إلى جهاز على الشبكة الداخلية). |

باختصار: المشروع **وسيط إرسال SMS** وليس تطبيق رسائل كامل المعنى (لا يدير اشتراكات المستخدمين، لا يستقبل SMS واردة من الشبكة في هذا الإصدار).

---

## 2. المتطلبات والتثبيت

- **PHP** مع امتدادات: `pdo_mysql`, `curl`, `json`, `mbstring`.
- **MySQL / MariaDB**.
- **Apache** (أو أي خادم يخدم PHP) — المسار الافتراضي المحلي غالباً `http://localhost/sm/`.

### خطوات أولية

1. انسخ `config.php` وعدّل `db` و`transport` و`api.key` و`cloud` حسب بيئتك.
2. افتح **`install_db.php`** مرة واحدة من المتصفح لإنشاء قاعدة البيانات والجداول (`sms_logs`, `api_server_inbox`).
3. احذف أو احمِ **`install_db.php`** في الإنتاج.
4. تأكد أن **`api.key`** غير فارغ حتى يعمل `api/send.php`.

---

## 3. الإعدادات (`config.php`)

| المفتاح | الدور |
|---------|--------|
| `db.*` | اتصال MySQL لحفظ السجلات. |
| `transport` | `cloud` أو `local` — يؤثر على السلوك الافتراضي عندما لا تُمرَّر كل بيانات الـ Gateway في الطلب. |
| `cloud.*` | عنوان واجهة السحابة + اسم المستخدم وكلمة المرور **اختيارية** للاستدعاءات التي لا ترسل `cloud_*` في JSON. |
| `gateway.*` | قيم افتراضية لحقول وضع **محلي** في الواجهة فقط. |
| `api.key` | مفتاح سري لطلبات `api/send.php`. |
| `api.cors_origin` | إن وُضع، يُفعَّل CORS للمتصفحات من ذلك الأصل فقط. |

## 4. كيف يعمل المشروع (معمارية وتدفق)

### 4.1 الملفات الأساسية

| الملف / المجلد | الوظيفة |
|----------------|---------|
| `index.php` | نموذج إرسال يدوي؛ يستدعي `sm_run_sms_dispatch()`. |
| `api/send.php` | **REST**: `POST` + JSON + `X-API-Key` أو `Authorization: Bearer`؛ نفس نواة الإرسال + تسجيل `api_server_inbox`. |
| `includes/sms_dispatch.php` | يقرر المسار (محلي مقابل سحابة)، يتحقق من الحقول، يستدعي الـ Gateway، يكتب `sms_logs`. |
| `includes/sms_gateway.php` | `cURL`: `POST` JSON + **Basic Auth** نحو URL البوابة. |
| `includes/db.php` | `sm_config()`, `sm_db()`, ترحيلات خفيفة لبنية الجداول. |
| `includes/api_inbox.php` | تسجيل طلبات السيرفرات في `api_server_inbox` (بدون كلمات مرور في JSON المخزّن). |
| `operations.php` | عرض `sms_logs` مع ترقيم صفحات. |
| `server_inbox.php` | عرض طلبات الـ API الواردة. |
| `test_connection.php` | تشخيص اتصال البوابة دون كتابة في السجل. |
| `api-demo.html` | شرح ومحاكاة للـ API من المتصفح. |
| `code_form_sennd_my_server.php` | **مثال عميل** ينادي `api/send.php` من سيرفر/نطاق آخر (انظر القسم 7). |

### 4.2 تدفق طلب ناجح عبر الـ API

1. العميل يرسل `POST` إلى `api/send.php` مع ترويسة المفتاح وجسم JSON.
2. التحقق من المفتاح، ثم فك JSON، ثم إدراج صف في **`api_server_inbox`** (نسخة JSON منزوعة كلمات مرور البوابة).
3. **`sm_run_sms_dispatch`**:
   - إذا وُجدت `gateway_url` + `gateway_username` + `gateway_password` → إرسال **محلي** (رقم واحد لكل طلب).
   - وإلا → **سحابة**: إما الحقول `cloud_api_url`, `cloud_username`, `cloud_password` في JSON، أو القيم في `config.php` إن اكتملت.
4. طلب `cURL` إلى البوابة؛ اعتبار التسليم ناجحاً عند **HTTP 2xx** وبدون خطأ `cURL`.
5. إدراج **`sms_logs`** بنتيجة الإرسال.
6. تحديث صف `api_server_inbox` وإرجاع JSON (يشمل `log_id`, `inbox_id`, `delivered`, `http_code`, `gateway_response`, …).

**مهم للعميل البرمجي:** الحقل `success: true` في الرد يعني أن المسار اكتمل وحُفظ السجل؛ **التسليم الفعلي للمزوّد** يُبنى على **`delivered`** و`http_code` و`gateway_response`.

### 4.3 وضع السحابة مقابل المحلي

- **سحابة:** السيرفر يرسل JSON إلى `api.sms-gate.app` (أو عنوانك)، والهاتف الذي يشغّل التطبيق يكون **متصلاً** ويستلم الأمر من السحابة.
- **محلي:** السيرفر يرسل إلى عنوان LAN (مثل تطبيق Android SMS Gateway على نفس الشبكة) — مناسب إن لم تُرسل الرسائل عبر الإنترنت.

## 5. الأمان والممارسات الموصى بها

- **لا ترفع `config.php` أو ملفات تحتوي مفاتيح حقيقية** إلى مستودع عام دون `.gitignore`.
- استخدم **HTTPS** بين العميل وسيرفر `sm` وبين `sm` والسحابة في الإنتاج.
- **`code_form_sennd_my_server.php`** حالياً يضع المفتاح وبيانات السحابة **داخل الملف** — مناسب للتجربة فقط؛ في الإنتاج استخدم **متغيرات بيئة** أو ملف إعدادات خارج جذر الويب وصلاحيات مقيدة.
- غيّر **`api.key`** إذا تسرّب، وراجع كلمات مرور السحابة إن وُجدت في سجل Git أو نسخ احتياطية عامة.

## 7. دراسة ملف `code_form_sennd_my_server.php`

هذا الملف **ليس جزءاً من نواة البوابة**؛ هو **عميل (Client)** يوضّح كيف ينادي نظام خارجي (أو نفس النطاق) نقطة **`api/send.php`** على سيرفر مشروع `sm`. الاسم يحوي إملاءً (`sennd` بدلاً من `send`) — يمكنك إعادة تسميته لاحقاً لتجنب الالتباس.

### 7.1 السطور 1–6: الترويسة والإعدادات

```php
declare(strict_types=1);
```

تفعيل الأنواع الصارمة لتقليل أخطاء التحويل.

```php
$apiUrl = 'https://.../api/send.php';
$apiKey = '...';
```

- **`$apiUrl`**: يجب أن يشير إلى **المسار الكامل** لـ `send.php` على السيرفر الذي يشغّل مشروع `sm`.
- **`$apiKey`**: يجب أن يطابق **`api.key`** في `config.php` على ذلك السيرفر؛ وإلا يرد الـ API بـ **401**.

> **تحذير:** إن كان الملف يحتوي على مفتاح وبيانات سحابة حقيقية، تعامل معه كسرّي: لا تنشره، وانقل القيم إلى بيئة آمنة بعد الاختبار.

### 7.2 السطور 7–13: جسم الطلب (`$payload`)

```php
$payload = [
    'phone_number'   => '...',
    'message'        => '...',
    'cloud_api_url'  => '...',
    'cloud_username' => '...',
    'cloud_password' => '...',
];
```

- **`phone_number`**: رقم المستلم (يمكن أيضاً استخدام `phone` أو مصفوفة `phoneNumbers` حسب ما يدعمه `api/send.php`).
- **`message`**: نص الرسالة بعد التشذيب في السيرفر.
- **`cloud_*` الثلاثة:** عند اكتمالها، يستخدم `sm` **بيانات السحابة المرسلة في الطلب** ولا يعتمد على `cloud.username` / `cloud.password` في `config.php` لهذا الطلب تحديداً. هذا مفيد عندما يكون عميلك على سيرفر لا يملك ملف `config` الخاص بـ `sm` لكنك تريد تمرير اعتماد السحابة لكل طلب.

إن أزلت حقول `cloud_*` وكان على سيرفر `sm` قد ضُبط `cloud.username` و`cloud.password` في `config.php`، يكفي إرسال `phone_number` و`message` فقط.

### 7.3 السطور 15–25: إعداد cURL

- **`CURLOPT_POST` + `CURLOPT_POSTFIELDS`**: إرسال JSON كجسم الطلب.
- **`Content-Type: application/json`**: مطلوب لأن السيرفر يقرأ `php://input` كـ JSON.
- **`X-API-Key`**: أحد الطريقتين المعتمدتين للتوثيق (البديل: `Authorization: Bearer <key>`).
- **`CURLOPT_TIMEOUT`**: حد أقصى لانتظار الرد (45 ثانية) لتجنب تعليق العملية.

### 7.4 السطور 27–31: التنفيذ وجمع الأخطاء

- **`curl_exec`**: يعيد نص الرد الخام (JSON من `sm`).
- **`curl_errno` / `curl_error`**: تفشل عند مشاكل DNS، TLS، انقطاع، timeout قبل أن يصل أي رد HTTP.

### 7.5 السطور 33–46: الرد للمتصفح أو للعميل

- يُعاد توجيه المخرجات كـ **`application/json`**.
- عند فشل cURL: كائن بسيط `{ "ok": false, "curl_error": "..." }`.
- عند النجاح: يُعاد **`http_status_from_sm`** (مثل 200، 400، 401) و**`body`** إما مصفوفة مفكوكة أو النص الخام إن لم يكن JSON صالحاً.

هذا يسهل ربط نفس السكربت لاحقاً بـ AJAX أو بخدمة خلفية أخرى دون تغيير جوهر الاتصال بـ `sm`.

### 7.6 ماذا يتوقع العميل في `body` بعد نجاح HTTP 200؟

من منطق `api/send.php` (باختصار): `success`, `log_id`, `inbox_id`, `delivered`, `http_code`, `gateway_response`, `curl_error`, `transport`, `cloud_credentials_source`. راقب **`delivered`** لمعرفة إن كانت البوابة الخارجية قد قبلت الإرسال بنطاق 2xx.

### 7.7 تحسينات مقترحة على الملف النموذجي

1. قراءة `$apiUrl` و`$apiKey` من **`getenv()`** أو ملف `.env` خارج الويب.
2. عدم تثبيت رقم هاتف ورسالة في الكود؛ تمريرها من `$_POST` أو من طابور مهام.
3. إضافة **`CURLOPT_CONNECTTIMEOUT`** للاتصال الأولي.
4. في الإنتاج: **HTTPS** فقط، والتحقق من شهادة السيرفر إن لزم (`CURLOPT_SSL_VERIFYPEER`).

## 8. الخلاصة

مشروع **`sm`** يوفّر **وسيط إرسال SMS** مع واجهة بشرية و**API** للأنظمة الأخرى، وتسجيل في قاعدة البيانات، ودعم سحابة أو Gateway محلي. ملف **`code_form_sennd_my_server.php`** يمثل **أبسط عميل PHP** يوضح عقد الاتصال: عنوان `send.php`، مفتاح API، وJSON يتضمن الرسالة وبيانات السحابة عند الحاجة. لدمج أي نظام آخر، انسخ نفس الفكرة بلغتك (Node، Python، …) مع الحفاظ على الترويسة وجسم JSON المتفق عليهما.
